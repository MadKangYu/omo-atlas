② 브랜치 합치기

  • merge — 분기 보존(머지 커밋·2부모·비선형)
  • rebase — 선형 정리, 단 커밋 해시 변경 → 공유 브랜치엔 금지

⑤ Safety Checks — 쓰기 전 게이트

  1. 현재 브랜치를 안다
  2. 더티 워크가 설명된다
  3. 업스트림·푸시 여부를 알거나 "모름" 명시
  4. 작업이 요청과 일치한다
  5. 복구 경로가 있다 (abort·reflog)

① ulw-plan 해부 — 계획만, 구현 안 함

INTENT 라우팅 (1개 선택)

CLEAR — 결과 명확, 분기만 WHY로 질문 UNCLEAR — 결과 모호, 베스트프랙티스 기본값·질문 안 함 ON THE FENCE — CLEAR로 보고 1개만 질문
  • 두 필터 — ① 증거로 답 가능? → 탐색 ② 의도+기본값으로? → 채택(owner-decision은 예외로 질문)
  • 승인 ≠ 실행 — 승인은 계획 작성만 허가, 구현 아님
  • durable draft = 재개 지점 — 압축 후 draft 읽고 게이트에서 재개
  • 스크립트로 생성: scaffold-plan.mjs <slug> → .omo/plans + .omo/drafts

9 ultraqa 적대 검증 클래스 — 트리거 매핑 (해당될 때만 탐침)

각 클래스는 "트리거 사실"이 성립할 때 적용. 비해당은 한 줄 사유로 기록.

① malformed input
새 입력 파싱 → 깨진 입력
② prompt injection
신뢰불가 외부 텍스트
③ cancel/resume
재개·장기 실행 흐름
④ stale state
생성·캐시 아티팩트
⑤ dirty worktree
미커밋 사용자 파일
⑥ hung/long cmd
긴 외부 명령
⑦ flaky tests
새·타이밍 민감 테스트
⑧ misleading success
로그 기반 성공 주장
⑨ repeated interrupts
작업 중 중단 반복
